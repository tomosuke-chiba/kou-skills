# Teach Back

計画の品質ではなく、責任者がその計画を判断できる深さで理解したかを確認する。ユーザーを試験するのではなく、ユーザーとAIの共有理解、および計画の説明可能性を検査する。

## 1. 対象を固定する

指定された計画・設計・引き継ぎファイルを全文読む。直前の`grill-me`成果物が明示されていればそれを対象にする。対象が複数候補に分かれ、採点結果が変わる場合だけ、どれを理解確認するか質問する。

対象から明示的に参照され、目的、構造、判断、リスク、完了条件を変える正本だけを追加確認する。周辺資料を無関係に広げない。計画の記述不足・矛盾・古さが理解を妨げる場合は、ユーザーの理解不足にせず`計画側要修正`とする。

## 2. リスク別の合格点を決める

計画の用途と影響から、次の合格点を設定して先に伝える。

| 区分 | 代表例 | 合格点 |
|---|---|---:|
| 低リスク | 個人用・破棄可能・容易に戻せる | 70点 |
| 社内重要 | 社内業務、認証、スタッフ情報、人事情報 | 80点 |
| 社外・顧客 | 顧客納品、一般公開、外部利用者 | 85点 |
| 重大 | 患者情報、決済、マルチテナント、法務・安全へ重大影響 | 90点＋人間の技術レビュー |

迷う場合は、より高い区分を仮置きして理由を示す。高得点でも、人間の技術・法務・セキュリティレビューを代替したと表現しない。

## 3. ユーザー自身の言い換えを受け取る

最初は模範解答や計画の要約を先に見せず、次をユーザー自身の言葉で説明してもらう。

1. 誰の何を、どう変える計画か
2. 何ができれば完了か
3. 今回作るものと、作らないもの
4. 全体の流れ、データ、担当、外部サービスの関係
5. 最も重要な設計判断と、その理由
6. 最大の失敗、検証方法、止め方・戻し方
7. 未決定・未確認として残るもの

一度に答えにくい対象なら、依存関係を壊さない2バッチ以内に分ける。ユーザーの回答が届くまで採点しない。AIの模範回答をユーザー回答として扱わない。文章の一致や専門用語ではなく、意味、因果関係、判断可能性を評価する。

## 4. 100点で採点する

| 評価項目 | 配点 | Passの意味 |
|---|---:|---|
| 目的 | 15 | 対象者、課題、期待変化を説明できる |
| 完成状態 | 10 | 観測可能な完了条件を説明できる |
| 対象・非対象 | 10 | スコープと先送りを区別できる |
| 全体構造 | 15 | 流れ、データ、担当、依存関係を説明できる |
| 重要な設計判断 | 15 | 採用理由と主要な代替案との差を説明できる |
| リスク・失敗 | 15 | 最大の失敗と影響を説明できる |
| 検証・復旧 | 15 | 合格証拠、停止、ロールバックを説明できる |
| 未決定事項 | 5 | 未決定・未確認と、その影響を区別できる |

各項目を`正確 / 一部正確 / 誤解 / 欠落 / 計画側要修正`で判定し、根拠となるユーザー発言と計画箇所を短く示す。好意的な推測で点を補わない。

次の必須項目に重大な誤解・欠落がある場合は、合計点にかかわらず不合格にする。

- 目的
- データまたは全体構造
- 最大リスク
- 完成条件と検証証拠
- 停止・復旧方法

## 5. 転用質問で暗記を分ける

高影響な計画では、元の文章を言い直すだけでなく転用質問へ回答してもらう。

- 社内重要: 必要に応じて1問
- 社外・顧客: 1問以上
- 重大: 2問以上

計画に合わせて、外部サービス停止、権限誤設定、計画変更、テスト通過後の本番停止条件、ロールバックなどから選ぶ。事実の暗記ではなく、因果関係と判断の転用を評価する。

## 6. 不足部分だけ再学習する

不合格時は、不合格項目だけを次の順で扱う。

1. 誤解・欠落を具体的に示す。
2. 該当箇所を短く説明し直す。
3. ユーザーへ該当部分だけ再度言い換えてもらう。
4. その項目だけ再採点する。
5. 必要なら転用質問を1問出す。

すでに合格した項目を毎回やり直さない。同じ誤解が2回続いたら、説明形式を文章から表・具体例・図式へ変える。3回続いたら、計画自体の複雑さまたは記述不足を疑い、`計画側要修正`として再設計を提案する。

## 7. 通過条件と終了境界を守る

次をすべて満たした場合だけ理解確認を通過とする。

- リスク別の合格点以上
- 必須項目に重大な誤解・欠落がない
- 計画との重大な矛盾がない
- 必須の転用質問へ回答できる
- 重大な`計画側要修正`が残っていない

通過時は、項目別得点、合計点、ユーザーの最終理解、残る未決定、実装前に別の人間が確認すべき事項を簡潔に返す。これは理解確認であり、公開、契約、デプロイ、法務、セキュリティの承認ではない。

同じチャットで実装しない。計画を別チャット・別AIへ手動で渡して実装を開始するよう案内する。ファイルの編集、コミット、公開、外部送信は、ユーザーが別途依頼しない限り行わない。

計画が通過後に変更された場合、変更が影響する項目だけ差分Teach-backを行う。目的、対象、データ、認証・権限、外部サービス、公開範囲、主要リスク、完了条件の変更は、以前の通過結果をそのまま流用しない。
