# Decomposition heuristics

## Count by belief change

Start with one slide per audience belief change. A belief change is a sentence the audience should accept before the next sentence can land.

Split when any condition is true:

- Two independent conclusions compete for attention.
- The content moves from a question to an answer and suspense is useful.
- A claim and its analogy each need a separate visual focal point.
- A problem analogy and a solution analogy perform different roles.
- The central relationship changes between comparison, sequence, cause-effect, cycle, or proof.
- More than three phrases need emphasis.
- The slide would require more than two large cards, three small cards, or five independent text groups at the reference deck's type size.

## Beginner concept gate

Before fixing the count, list every tool, skill, file, workflow stage, abbreviation, and technical term that may be new to the audience.

For each new concept, cover this sequence before the first action:

1. `What`: one short definition and one dominant visual.
2. `Why`: the problem it prevents or the value it creates.
3. `How`: only the minimum action needed in the current section.

Default to one slide for `what` and another for `why`. Merge them only when one visual sentence communicates both within three seconds with large seminar-readable type.

Do not treat a fixed slide count as a constraint for beginner comprehension. If content is dense, split it. Never solve density by shrinking text.

Move long prompts, commands, detailed checklists, and exception handling into a named companion handout. Slides may show the prompt's purpose, required input, expected output, and pre-run confirmation.

Merge when all conditions are true:

- The beats support the same audience conclusion.
- One diagram can show the relationship.
- The title, diagram, and bottom conclusion do not compete.
- The merged slide remains readable at seminar distance.

## Reference-density correction

Estimate a reference slide's capacity:

- Sparse: one hero phrase or one diagram. Use one beat per slide.
- Medium: one diagram plus two supporting groups. Merge only tightly coupled beats.
- Dense but readable: two large comparison cards, three process cards, or one table with one conclusion. Allow multiple facts only when they serve the same message.

Do not equate dense design with permission for multiple messages. Density changes how much evidence fits, not how many conclusions fit.

## Narrative roles

Use these common sequences when appropriate:

- Promise → doubt → honest limitation → analogy → mechanism → proof → payoff
- Current state → problem → consequence → new method → process → evidence → next action
- Question → misconception → correction → concrete method → repeatability → future value

## Count explanation

Always give:

1. Recommended count.
2. Why one fewer would overload a specific boundary.
3. Why one more would separate beats that belong together.
