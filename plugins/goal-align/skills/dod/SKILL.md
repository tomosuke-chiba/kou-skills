# 目的逆算思考DoD（木下勝寿式）

> 出典の考え方: 木下勝寿『時間最短化、成果最大化の法則』の「最終目的逆算思考」をTomの運用向けに一般化（Tom定義 2026-08-08）

## 4要素を分けて定義する（ここが核心）

| 要素 | 定義 | 例（新規集客施策の場合） |
|---|---|---|
| 1. **目的** | 何のためにやるか | 新規集客数を増やす／利益を増やす |
| 2. **目標** | 目的を具体化したターゲット | 新規集客数を月間1,000人→1,500人にする／利益を1円でも多く |
| 3. **答えの条件** | 目標を「◯◯になりさえすればいい」に変換した完了判定文＝**これがDoD** | 新規集客数が1,500人になりさえすればいい／利益が1円でも多くなりさえすればいい |
| 4. **検証方法** | 何の事実・数字で判定するか＋誰が判定するか | 月次集客レポートの実数／Tom確認 |

- 答えの条件が決まると**手段が自由化**される（どんなことをしてもいい）→ 最短ルート選択・途中の手段変更が可能になる
- **重いタスク**（数時間以上・複数人・事業数値に直結）: 4要素すべて定義
- **軽いタスク**（1時間未満・単独完結）: 目的＋答えの条件のみでOK

## 手順

1. 重さ判定（重／軽）
2. 目的の特定（複数可。「なぜやるか」を1段上に遡る。事業タスクは北極星KPI・利益への接続を確認）
3. 【重のみ】目標の確定: 数値・状態で書く。**未確定の数値は推測で置かずTomに質問**（❓要確認を付ける）
4. 答えの条件への変換: 各目標を「◯◯になりさえすればいい」の1文にする
5. 検証方法の確定（Claude自動判定／Tom目視のどちらかを明記）

## 出力形式

- 重タスク: `| 目的 | 目標 | 答えの条件（〜さえすればいい） | 検証方法・判定者 |` の表
- 軽タスク: 「目的: ◯◯」「答えの条件: ◯◯になりさえすればOK」の2行

## ソリューション展開（明示指示があったときだけ）

Tomが「ソリューションも出して」「木下式で解を考えて」「候補を出して」と指定したら、`kinoshita-solution` スキルを呼び、着眼法×2案＋苦情法×2案の計4案を展開する。**指示がなければDoD確定で止める**（勝手に展開しない）。

## ルール

- 目標の数値が未確定なら勝手に置かない。「❓要確認」を付けてTomに聞く（未検証数値を出さない方針と同じ）
- 答えの条件の確定後は手段に固執しない。条件を満たす限り手段変更は自由（いちいち承認不要）
- 逆に、答えの条件にない品質・機能の作り込みはOver-Engineering（やらない）
- AIへの委譲時は、答えの条件＋検証方法をそのまま委譲プロンプトの「✅評価項目」に載せる
- 詳細なテスト手順の粒度は `~/.claude/rules/dod-and-quality.md` のテンプレに準拠
