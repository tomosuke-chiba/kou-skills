## 質問・調査・AI判断の振り分け

次の式を比較の基本にする。

```text
質問コスト < 質問しなかったことで生じる期待追加コスト
```

- 質問コストには、回答時間、読解、判断、文脈切り替え、質問の累積疲労を含める。
- 期待追加コストは、誤解する確率と、追加の発見・確認・手戻り・下流影響を掛け合わせて考える。
- 高影響・不可逆・外部送信・公開・契約・決済・削除・権限変更などは、式だけでAI判断せず、人間の明示確認を優先する。

| 振り分け | 条件 | 記録すること |
|---|---|---|
| 調査 | 利用可能な信頼できる資料で確定できる | 結論、出典パスまたはURL、基準日、適用範囲、権威性、競合の有無 |
| AI判断 | 影響が小さく、可逆で、完成後の修正が安い | 採用内容、理由、影響範囲 |
| 質問 | 誤解の下流影響が大きく、人間の意図・価値観・承認が必要 | 背景、今決めること、選択肢、影響 |
| 明示的未決定 | 今決めなくても安全に進める、または必要情報がない | 判断基準、必要情報、影響、進行可能範囲 |

質問前に、少なくとも次を順に確認する。

1. 依頼文ですでに回答されていないか。
2. 指定資料、正本、コード、設定、テスト、ログから確定できないか。
3. 低影響・可逆としてAI判断できないか。
4. 今決めずに境界を明示して進められないか。
5. それでも結果差が大きい場合だけ質問する。

### 情報源探索の境界

調査のアンカーを、`指定された対象 → ユーザーが指定した資料・正本 → 対象に適用される統治ルール → アンカーから明示的に参照された資料` の順に置く。関連性は、同じ作業ディレクトリに存在することではなく、対象との明示的な関係と適用範囲で判断する。

- アクセスできるだけの周辺資料をタスクの適用正本とみなさない。
- 周辺資料が有用な手掛かりでも、対象への適用が確認できるまでは `候補` または `未確認` とする。
- ルールや現在値を質問の前提に使う場合は、`この情報源は何にだけ適用されるか` という適用対象を一文で明示する。
- 適用対象を説明できない情報源は、質問の前提や確定事項に使わない。
- 対象固有の正本が見つからない場合は、別用途の正本を流用せず、対象の現行ルールを `未確認` とする。
- Notion、Drive、Web、別リポジトリ、外部サービスなどへ調査を広げる必要がある場合は、必要性、対象、得られる判断材料を示し、ユーザーの許可後に読む。
- 現在値は基準日、取得日時、データ源、速報・確定の別を確認できない限り、過去資料から推測しない。

## 状態と証拠の台帳

### 判断の由来

| ラベル | 意味 | 遷移ルール |
|---|---|---|
| `ユーザー意図` | ユーザーが元から持ち、明示または確認した意図 | 明示発言か確認回答なしに付けない |
| `AIの理解・仮説` | AIが証拠から組み立てた未確認の解釈 | 確認後はユーザー意図へ移すか、否定して履歴を残す |
| `共同決定` | 未決定だった論点を、提案と対話で確定した | 採用理由と決定時点を残す |
| `AI判断` | 質問せずAIが採用した低影響・可逆な判断 | 理由と修正可能範囲を残す |
| `未決定` | 意図的に決めていない | 判断方法、影響、進行可能範囲を必ず添える |
| `未確認` | 必要な証拠を確認できない | 不明を事実として扱わない |
| `競合` | 信頼できる情報や意図が食い違う | 両論と、人間が裁定する論点を残す |

### 証拠の確度

判断の由来とは別軸で、主張を `事実`、`推定`、`未確認`、`競合` に分類する。計画、TODO、提案は実施意図の証拠であり、完了の証拠として扱わない。現在値には基準日を付ける。

調査結果を質問の背景や最終成果物へ使うときは、主張の近くに出典パスまたはURLを置き、情報源の適用範囲、権威性、ライフサイクルを保持する。部署限定、用途限定、期間限定のルールを組織全体へ拡張しない。ドラフトや提案を現行ルールとして一般化しない。適用できるか不明なら `未確認`、複数の正本が食い違うなら `競合` とする。

決定を残すときは、最低限、`論点 / 採用内容 / 由来 / 理由 / 重要な代替解釈 / 不採用理由 / 根拠 / 下流影響` を記録する。重要でない捨て案は列挙しない。

同じテーマの地図を更新するときは、最新状態を先頭へ反映し、変更された判断を黙って消さない。`変更日 / 変更対象 / 旧理解 / 新理解 / 由来 / 理由 / 下流影響` を判断・変更履歴へ圧縮して残す。生の会話ログやテーマ横断の人物プロファイルは保存しない。

## 質問契約

### すべての質問に共通する形

質問だけを別画面で読んでも答えられるよう、次を短く添える。

1. 背景と現在の共有認識
2. 用語または対象範囲
3. 今決めること
4. この回答が変える下流判断

### 質問の種類を分ける

| 種類 | 聞き方 | 推奨の扱い |
|---|---|---|
| 既存意図の確認 | `AIの理解・仮説` を示し、正しいか、どこを直すか聞く | 推奨を出さない |
| 価値観・好みの確認 | 同じ軸・同じ粒度の中立な選択肢を示す | AIの好みで誘導しない |
| 未決定事項の共同設計 | 実行可能な案を比較し、採用案を決める | 推奨と理由を示す |
| 高影響行為の確認 | 対象、作用、不可逆性、外部影響を具体化する | 明示確認を求める |

既存意図を確認するときは、次の形を使う。

```markdown
共有認識: <確認済みの事実>
AIの理解・仮説: <元の意図だと解釈している内容>
確認: この理解で正しいですか。違う場合は、どこをどう直すか教えてください。
影響: <確認後に確定できる下流事項>
```

共同設計するときは、次の形を使う。

```markdown
🎯 今決めること: <一つの判断軸>
背景: <前提なしで答えるための短い説明>
💡 推奨: <案>
理由: <目的と制約に照らした理由>

A. <案A> — 利点: <...> / 代償: <...>
B. <案B> — 利点: <...> / 代償: <...>
C. <案C> — 利点: <...> / 代償: <...>

影響: <この回答で変わる下流判断>
```

### バッチ化と依存順

- 前提がすべて確定した未解決論点を `依存関係の手前` とする。
- 同じ背景を共有し、その時点ですべて回答可能な手前の論点はまとめる。
- 一つの回答が別質問の意味、選択肢、推奨を変える場合は、上流質問だけを先に出す。
- 構造化質問ツールが一度に扱える件数を超える場合は、同じ文脈を壊さない最小バッチに分ける。
- ユーザーがまとめて回答できると明示した場合も、依存質問を先回りして混ぜない。独立論点はUI上限まで積極的にまとめる。
- 回答後に台帳と依存関係を更新してから、次の質問を作る。

### A/B/Cの品質条件

- 同じ判断軸、同程度の具体度、同程度の実行可能性で比較する。
- 各案が異なる優先目的に対して合理的な選択になるようにする。
- 利点と代償を同じ粒度で示す。
- 推奨案を具体化し、他案を曖昧な捨て案にしない。
- 重複案、数合わせ、明らかな不採用案を置かない。
- 良い3案を作れない場合は、A/Bの2案にするか判断軸を組み直す。3案を捏造しない。

## 成果物契約

実行時の成果物は、参照資料の数にかかわらず1ファイルにまとめる。見出し名や章数は対象に合わせて変えてよいが、次の意味を欠落させない。

### 第1層: 人間が30秒で理解する面

- テーマ
- 上位目的と、本当に達成したい状態
- 現在地と基準日
- ゴール、期限、完成条件
- 採用ルートと、最優先のルート選択基準
- 最終成果、先行指標、重大ガードレール、中間地点
- 読者が次に判断すること、次に実行すること
- 一番重要な3点

### 第2層: 後続AIが推測せず実行する面

- 元の依頼と、本当に達成したい状態
- 必要な前提知識と用語
- 正本・証拠と、事実・推定・未確認・競合の区分
- 現在地のベースライン、資産、過去施策と結果、関係する役割、ボトルネック、データ鮮度
- ゴールの対象、X、Y、期限、測定または観測契約
- ルート候補、ルート選択基準の優先順位、トレードオフ、採用理由
- 採用ルートの中間地点、最終成果、先行指標、ガードレール、見直し・停止・交換条件
- スコープ内、スコープ外、明示的な先送り
- 決定事項、決定の由来、理由
- 重要な代替解釈と不採用理由
- 要件、成功条件、観測可能な受入条件
- 制約、禁止事項、依存関係、リスク
- 未決定事項、判断基準、必要情報、影響、進行可能範囲
- 実行計画、依存順、担当、各工程の観測可能な完了条件
- 最新地図の基準日、古くなった前提、判断・変更履歴
- 次に判断することと、次に実行すること
- 理解チェック

### 自己完結性の条件

- 外部リンクは証拠や詳細確認に使い、主要な前提や判断をリンク先だけに置かない。
- 外部資料を全文複製せず、読めなくても判断と実行を再現できる要点を本文へ埋め込む。
- 生の会話ログではなく、採用解釈、由来、理由、重要な別解釈、不採用理由を構造化する。
- 秘密情報、認証情報、不要な個人情報を含めない。
- 不明な情報を捏造せず、`未確認`または`競合`として影響を示す。
- `未決定`を空欄やTODOにせず、誰が何を基準に決めるかを示す。
- 実行計画の各工程に担当または`要割当`と、観測可能な完了条件を置く。
- ルートを選ぶ評価基準と、選んだルートの進捗指標を別の見出しまたは表で示す。
- 直接測れないゴールでは数値を捏造せず、代理指標、観測条件、または学習ゴールを置く。
- 同じテーマの更新では新規ファイルを増やさず、最新地図と圧縮した判断・変更履歴を同じファイルに置く。
- 特別な `Draft / Approved` 状態や承認文言を追加しない。

## 品質ゲート

最終ファイルを渡す前に、次をすべてPass/Failで判定する。平均点で相殺しない。

### 1. 認識一致性

**Pass:** ユーザー意図、AIの理解・仮説、共同決定、AI判断、未決定が区別され、確認済み意図の矛盾・欠落がなく、明示されたスコープ外が実行対象へ混入していない。

### 2. 引き継ぎ再現性

**Pass:** 前の会話を知らないAIがその1ファイルだけを読み、目的、完成状態、スコープ、重要判断、未決定境界、実行順序を再現でき、文書の欠落を理由とする重要な追加質問を必要としない。

### 3. 対話合理性

**Pass:** 調査可能事項を質問せず、質問した方が安い重要論点だけを聞き、同じ文脈をまとめ、依存順を守り、選択肢を同等品質で提示している。

### 4. 地図実行性

**Pass:** 現在地、ゴール、ルート選択、ルート進捗、道路事情が揃い、数値・観測条件・期限・評価基準・見直し条件から、勝敗と次の行動を同じ定義で判断できる。

### 完了前チェック

- [ ] 暗黙の重要な未決定がゼロである。
- [ ] 事実、推定、未確認、競合を区別している。
- [ ] 判断の由来と証拠の確度を混同していない。
- [ ] 高影響・不可逆な分岐を人間が明示確認している。
- [ ] 現在地、ゴール、ルート選択、ルート進捗、道路事情が揃っている。
- [ ] 現在値に基準日と情報源があり、未確認値を推測していない。
- [ ] ゴールが数値と期限、または代理指標・観測条件・期限で判定できる。
- [ ] ルート選択基準とルート進捗指標を混ぜていない。
- [ ] 先行指標を正解扱いせず、必要な場合は機序、品質条件、想定遅延、反証・交換条件がある。
- [ ] 重大な品質・安全・倫理・利益・負荷・情報保護リスクにガードレールがある。
- [ ] 人間向け30秒面と、後続AI向け実行面が同じ1ファイルにある。
- [ ] 未決定事項に判断方法、必要情報、影響、進行可能範囲がある。
- [ ] 実行工程に依存順、担当、観測可能な完了条件がある。
- [ ] 理解チェックが再現・構造化・転用の3方向を含む。
- [ ] 同じチャットで実装していない。
- [ ] 事業計画・重要設計・高影響な依頼では、30秒面への訂正・確認を受けた次の応答で`$teach-back`を実行し、開始時に再要約・模範回答を示さず、通過前に共通認識到達を宣言していない。
- [ ] 低影響で可逆な依頼では、Teach-backを実行するか一度だけ確認している。
- [ ] 認識一致性、引き継ぎ再現性、対話合理性、地図実行性がすべてPassである。

理解チェックには最低限、次を答えられる問いを置く。

- **再現:** 目的と完成状態を一文で説明できるか。
- **構造化:** 現在地、決定、未決定、依存関係を区別できるか。
- **転用:** 次の判断と実行を、過去チャットなしで開始できるか。

## Skill改善時のフレッシュコンテキスト評価

この評価はSkillの作成・改訂時だけに行う。通常の `grill-me` 実行ごとに自動で別エージェントを起動しない。

新しいコンテキストへ改訂Skillと生の依頼だけを渡す。意図した回答、期待結果、疑っている欠陥、修正方針をテスターへ漏らさない。評価役は可能な限り読み取り専用にする。

最低限、次の挙動を生のケースで確認する。

1. 既存意図の確認で、AIの推奨をユーザー意図として混入しない。
2. 未決定事項の共同設計で、推奨と理由を出す。
3. リポジトリ調査で答えが出る事項をユーザーへ聞かない。
4. 修正容易な低影響事項をAI判断する。
5. 高影響の解釈分岐を質問し、同じ文脈をまとめ、依存質問を後へ送る。
6. A/B/Cの全案が同程度に具体的で、異なる価値基準なら合理的に選べる。
7. 最終成果物だけで、前提のない別AIが目的、決定、未決定、実行計画を再現できる。
8. 曖昧な事業相談で、現在地、X→Y→期限、ルート選択基準、進捗指標を分離して引き出す。
9. 数値化が難しい新規事業で、作業量を成果に見せず、代理指標または学習ゴールを提案する。
10. 同じテーマの再開で新規ファイルを乱造せず、最新地図と判断・変更履歴を更新する。
11. 先行指標に因果機序、品質条件、想定遅延、反証・交換条件を置き、ガードレールを確認する。
12. 広範な外部調査が必要な場合、必要性と対象を示して許可を待つ。
13. 独立質問をまとめ、回答によって意味が変わる依存質問だけを後続へ送る。
14. 重要案件で、地図確定後にTeach-backへ進み、未通過なら認識到達を宣言しない。

4つの品質基準を個別にPass/Fail判定する。Fail時は該当箇所だけを修正する。同じ失敗を2回繰り返したら評価方法または設計を変え、3回で停止して再計画する。
