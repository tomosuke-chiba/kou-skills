## 現在地

最低限、次を基準日付きで確認する。全項目を機械的に質問せず、正本、コード、データ、履歴から先に調べる。

| 項目 | 確認すること |
|---|---|
| 上位文脈 | 誰のどの価値を変えるためのテーマか。今集中する理由は何か |
| ベースライン | 現在値X、単位、対象期間、データ基準日、データ源、速報/確定 |
| 利用可能な資産 | 既存資料、コード、データ、顧客接点、担当能力、予算、時間 |
| 既往歴 | 誰がどの役割で、いつ、何を試し、何が起き、何を学んだか |
| ボトルネック | ゴールを最も制約している工程、意思決定、能力、データ、外部要因 |
| 運用状態 | 未開始、実行中、停止中などの事実。予定と実績を分ける |
| 不確実性 | 未確認値、競合する正本、古い前提、権限不足、測定不能箇所 |

個人名や人物一般の性格を蓄積しない。役割、テーマ内の判断原則、採用理由だけを残す。現在値をローカル計画書や古いスナップショットから推測しない。

## ゴールとWIG

### 成果ゴール

原則として次の形へ落とす。

```text
[対象] の [直接結果] を、[基準日・対象期間] の X から、[期限] までに Y へ変える。
```

短い一文とは別に、測定契約を持つ。

- 上位目的と顧客・業務価値
- 結果責任者と決定者
- X、Y、単位、期限、基準日、対象期間
- 分子、分母、対象、除外、重複、取消・返金等の計数規則
- データ源、更新頻度、確定までの遅延、データ責任者
- 目標軌道と達成判定
- 定義変更履歴

数値が未確認なら創作しない。`Unknown` とし、確認者、確認先、方法、期限を置く。直接定量化できない場合は、代理指標と観測可能な定性的条件を併用する。

### 学習ゴール

未知の商品、新市場、研究、測定未接続、主要ボトルネック未確認では、作業量を成果に見せない。次の形を候補にする。

```text
[期限] までに [最重要仮説] を、[対象・件数・比較] と [採択/棄却基準] により判断可能にする。
```

機能数、会議数、資料作成数は通常、成果WIGではなくマイルストーンまたは先行候補である。

## ルート選択

現在地とゴールをつなぐ現実的なルートを最大3案まで作る。評価項目を先に洗い出し、優先順位を必ず決める。数値の重み付けは、ルート差や投資影響が大きく、点数化が判断を改善する場合だけ使う。

候補となる評価項目:

- 上位目的・顧客価値への寄与
- ゴール到達の確率と現時点の根拠
- 到達速度と期限適合
- 費用、工数、能力、機会費用
- 既存資産の再利用可能性
- 可逆性と小さく試せる範囲
- 品質、安全、倫理、法令、情報保護
- 維持・委任・再現のしやすさ

固定チェックリストをそのまま採点せず、テーマで本当に重要な評価項目を `最優先 / 次点 / 守る最低条件` に分ける。ユーザーの価値判断とAI推奨を区別する。

各ルートは次で比較する。

| ルート | ゴールへの機序 | 主要評価項目 | 前提 | 代償 | 重大リスク | 最小検証 | 判定 |
|---|---|---|---|---|---|---|---|

## ルート進捗

採用ルートでは、指標を役割別に分ける。

| 種類 | 問い | 最低契約 |
|---|---|---|
| 最終成果・遅行 | ゴールの勝敗を直接判定できるか | 式、単位、対象、基準値、目標、期限、源、鮮度 |
| 先行指標 | チームが次周期に動かせ、結果より早く変わるか | 対象WIG、機序、品質条件、想定遅延、源、owner |
| ガードレール | 数字を追うことで何を壊し得るか | 閾値、監視頻度、停止・見直し条件、owner |
| 中間地点 | 期限までのどこで軌道を判定するか | 日付、必要状態、証跡、依存先 |
| 診断指標 | どこでルートが詰まったか分かるか | ファネル、セグメント、外部要因、データ品質 |

先行指標を正解扱いしない。次の因果仮説を置く。

```text
仮説: [先行指標] が [量/質] だけ変わると、[遅延] 後に [遅行指標] が動く。
機序: 行動 → 近位変化 → 顧客・業務変化 → 最終成果。
現時点の根拠: 公式経験則 / 外部研究 / 社内時系列 / 比較 / 実験 / なし。
代替説明: 季節性、案件構成、価格、広告、要員、制度、市場など。
反証・交換条件: いつ、どの状態なら修正または廃止するか。
```

先行・遅行は対象ゴールと時間幅に対して相対的である。活動回数には「適格」「完了」「有効」などの品質条件を組み込み、量だけの達成を防ぐ。

## スコアボードと実行リズム

重要な事業目標では、プレイヤーが短時間で勝敗と次の行動を判断できる表示を設計する。

1. ゴールと期限
2. 最終成果の実績、今日時点の必要軌道、最終目標
3. 先行1〜2個の実績、目標、品質条件
4. 重大ガードレール
5. データ基準日、速報/確定、データ源、更新責任者
6. 欠損、定義変更、予測の前提

個人ランキングや公開羞恥を標準にせず、チームが学習と説明責任に使う。欠損をゼロとして表示しない。

固定リズムは対象の結果遅延に合わせる。初期候補は `Account → Review → Plan` とする。

- **Account:** 前回の約束、証跡、完了・未完・学び
- **Review:** 勝敗、データ鮮度、予想との差、ボトルネック、指標の維持・交換
- **Plan:** 次周期の1〜2個の約束。担当、期限、成果物、品質、証跡、障害除去

日常業務の全案件報告を混ぜない。同じ約束が繰り返し未完なら、人格ではなく容量、権限、依存関係、粒度を再設計する。

## 失敗を防ぐ条件

- 狭い代理指標を、未検証のまま報酬・懲罰・個人ランキングへ直結させない
- 品質、安全、倫理、法令、利益、顧客負担、従業員負荷、情報保護の重大条件をゴールより優先する
- 先行が動いて遅行が動かない場合、行動量だけを増やさず、データ、遅延、品質、ファネル、外部要因、セグメント、因果仮説を順に疑う
- 成功事例や4DXの名称を因果証明として扱わない
- 目標、予定日、承認日、実開始日、停止日を遡及して書き換えない
- 外部現在値をローカル資料から推測しない

## 事業地図の完了条件

- 現在地XとゴールY、期限、対象、計数規則、データ鮮度が確認済みか、期限付きUnknownになっている
- 採用ルートが評価基準とトレードオフから説明できる
- 最終成果、先行、ガードレール、中間地点、見直し条件が役割別に分かれている
- 先行指標に機序、品質条件、想定遅延、反証・交換条件がある
- スコアボードと実行リズムが必要か判断され、必要な場合はownerと頻度がある
- 未決定事項に判断者、確認方法、期限、影響、進行可能範囲がある
- 数字を達成した結果、誰か・何かを壊す重大経路が残っていない
