# render-horizontal-interview — 横インタビュー（話者色分け）ルート

2026-07 みどりの歯科医院 DH木村さんインタビューで確立。**テロップ同期精度を最優先**するルート。
判断が要る箇所は全部ここに明文化してある。**モデルの賢さに頼らず、この手順とスクリプトに従うこと**（Sonnet 等でも同品質を出すための設計）。

## パイプライン全体

```
transcribe-words (words.json)
   ▼
LLM: カット設計 → cutplan.json        ← このスキルの「カット設計ルール」に従う
LLM: テロップ設計 → koetsu.json       ← smart-caption の鉄則＋このスキルの追加ルール
   ▼
scripts/render_interview.py           ← 以降は全部決定論的（スクリプト任せ）
   = カット → loudnorm 2パス → onset_snap → PNG焼き込み → MP4 + SRT
   ▼
qc-gate（sync は onset_snap --check 併用）→ 納品
```

## 呼び出し

```bash
python3 scripts/render_interview.py \
  --src "<元動画>" --work "<work_dir>" \
  --koetsu "<work_dir>/koetsu.json" --cutplan "<work_dir>/cutplan.json" \
  --out "<work_dir>/<stem>_fulltelop.mp4"
```

- `cutplan.json`: `{"drop_ranges": [[s,e],...], "end_time": <末尾カット位置>}`（src 秒）
- `koetsu.json`: `{"items":[{"start","end","speaker","text"}]}`（src 秒・speaker は `interviewer` / `respondent`）
- SRT は同名 `.srt` で自動出力（オンセットスナップ後の時刻）
- `--heading "見出しテキスト"` で左上見出し（heading-overlay スキルの固定デザイン・紺グラデ帯）を
  全編焼き込みできる（テロップPNGに合成する方式・追加入力なし）。完成済み動画への後掛けは heading-overlay スキル参照
- 既定スタイル: インタビュアー=白+黒フチ 72px／回答者=#FF3399+白フチ+薄影 74px。`--styles` で上書き
  （72/74 はユーザー確定値。勝手に小さくしない）

## 回答者スタイルの標準（2026-08 沖縄研修でユーザー確定・以降の標準運用）

回答者（respondent）テロップは **性別で色を使い分ける**。プリセットは `assets/` に同梱済み。
`--styles` に該当プリセットを渡す（渡し忘れると旧既定の #FF3399 細フチで焼かれるので必ず指定）：

- **男性** → `assets/styles_male_blue.json`（濃紺 RGB(42,53,168)＋白フチ10px・90px・紺影。Vlog選手権参考画像で確定）
- **女性** → `assets/styles_female_pink.json`（ピンク RGB(240,163,216)＋白フチ10px・90px・濃紺影。おさるさん系参考画像で確定）
- インタビュアーは既定の白72pxのまま変更しない

**性別の判定手順**（LLM の仕事・確定前に必ず両方見る）：
1. 動画フレームを数枚抽出して話者の外見を確認（話者が遠い場合はcropで拡大）
2. 音声ピッチで裏取り：発話区間の median F0 を測る（目安: 男性 80〜150Hz／女性 165〜255Hz。
   2026-08 実測例: 女性話者 198Hz）。遠距離マイクで測定不能なら映像判定のみでよい
3. 両方で確定できない場合はユーザーに確認（取り違えて焼くと再レンダリング1回分の損失）

**インタビュアーの質問は逐語テロップにしない**（2026-08 ユーザー確定）：
質問の発話区間全体に「Q. 〜は？」形式の**質問項目テロップ**を1枚表示する
（例: 「Q. 講義に参加した理由は？」「Q. 作ってみたいアプリ・サイトは？」）。
挨拶・相槌（よろしくお願いします／ありがとうございます等）は従来どおり逐語＋話者色分け。

**一人語り素材**（感想・デモ等でインタビュアー不在）は質問項目テロップなし・
全カード respondent として性別スタイルを適用する。

## カット設計ルール（LLM の仕事・word 境界で取る）

words.json のギャップ一覧（>0.45s を列挙）を見て `drop_ranges` を決める：

1. **1.0s 超の無音** → 前後に余裕を残して詰める（`drop = (gap_start+X, gap_end-0.20)`）。
   前側の X は **直前が文末語（〜です／〜ました／ありがとうございます 等の言い切り）なら 0.40s**、
   それ以外は 0.25s。**Whisper の word 終了は伸びる語尾で実際の声より早く付く**ため、
   0.25s だと「ありがとうございました〜」の語尾が切れる（2026-07 実測）
2. **0.5〜1.0s の無音は残す**（会話の自然な間。ユーザーが「無音は人の手で直す」方針なら特に触らない）
3. **フィラー**（そうですね／えっと／あのー）は word 境界ぴったりでカット。
   直後の語の word 開始時刻をカット終端にする（例: そうですね[158.95-159.48]→drop(158.95,159.48)）
   - **「うーんと」「えっと」は Whisper が書き起こさないことが多い**（2026-07 すすむ歯科で実測）。
     words.json に無くても、質問後のギャップ内に「音の島」として残り、**声は出ているのに
     テロップが無い＝ズレて見える**というユーザー指摘の主原因になる。回答冒頭のギャップは
     silencedetect で島を洗い出し、言い淀みの島は間ごとカットする
   - **回答冒頭の言い淀みクラスタの切り方**：孤立した「そうですね」（後ろに0.5s以上の無音）は
     うーんと・間ごとカットして本題から始める。**内容に地続きの「そうですね」（直後0.3s以内に
     本題が続く）は言葉として残し**、手前の無音だけ詰める（「ちゃんと言葉を発したタイミングは
     残したい」がユーザー要望）。境界は 質問の声のエネルギー終端+0.35s 〜 本題のエネルギー
     立ち上がり−0.25s
4. **言い直しブロック**（「言葉の使え…言葉の…」）は前後の無音ごと1つの drop にまとめる
5. **語中に埋まった「ちょっと」等は音声カットしない**。テロップ文から省くだけ（splice ポップ防止）
6. **末尾の撮影合図**（「はい、OKです」等）は `end_time` で除外。回答者のお辞儀・笑顔は余韻として残す。
   `end_time` は**最後に残す語の word 終了 +0.5s** を確保（語尾切れ防止）。合図の頭と重なって
   0.5s 取れないときは、エネルギー包絡で声が無音に落ちたのを確認できる位置まで確保する
   - **次の発話の直前で切る場合、次語の Whisper word 開始を終端にしてはいけない**（2026-07 とく歯科
     前事務局さん実測：「ありがとうございました」直後で切る指示で、次語「以上」の word 開始 177.78s は
     実際の声の立ち上がりより約 0.17s 早く付いていた＝ポーズ明けの語頭前倒し癖の裏返し）。
     `silencedetect`（noise=-40dB:d=0.03 等の細かい設定）で**実無音窓を特定し、その内側に end_time を置く**
   - **レンダリング後、出力末尾 0.5s の RMS 包絡（astats length=0.01）で減衰を確認**。
     語尾が自然にフェードして無音（-40dB 以下）に落ちて終わっていれば合格。
     -20dB 前後で打ち切られていたら声が残っている＝終端が早すぎる/位置ズレなので引き直す
     （同案件で end_time=177.80 は一見無音ギャップに見えたが出力検証で声が残り、177.94 に修正）
7. **迷ったら残す**。語尾の切り落としは目立つ事故、間が少し残るのは人の手で直せる
8. 目安圧縮率: インタビューで 12〜18%。**20% 超えたら削りすぎを疑う**
9. **Whisper のフル文字起こしは、オフマイクの相槌・低音量区間・長い言い淀みを丸ごと落とすことがある**
   （2026-07 とく歯科 徳田院長インタビューで実測：369〜377s の8秒区間で「あの」フィラー2箇所と
   本来の無音境界が全欠落）。**単独クリップの再文字起こしだけを信じるのも危険**（文脈が無いと
   Whisper は無音区間に単語を幻覚する。同案件で 1.75s の無音区間が別クリップ切り出しで
   "5" という架空の単語に化けた）。cutplan の drop_range 候補が word ギャップ由来ではなく
   「文字起こしが薄い/欠落した区間」に近いときは、**ffmpeg silencedetect のエネルギー基準を正**とし、
   複数の閾値（-38dB/-45dB 等）で一致する区間だけを信頼する。一致しない・境界が数百ms 単位で
   ブレる場合は原則7（迷ったら残す）を適用し、無理にフィラー除去を狙わず広めに無音ごと残す

## 保護フレーズ検証（挨拶・謝辞などの語頭/語尾切れ防止・必須）

「ありがとうございます／ました」等の決まり文句は、カットで語頭や語尾が数百ms 欠けても
気づかれにくく、かつ視聴者に一番目立つ事故になる。drop_range 確定前に必ず以下を行う：

1. words.json 全文から対象フレーズ（挨拶・謝辞・締めの言葉）を **冒頭・中盤・末尾すべて**リストアップ
   （インタビュアー／回答者を問わない。「はい、OK です」等の撮影合図と紛らわしい語尾にも注意）
2. `ffmpeg silencedetect=noise=-45dB:d=0.3` を **words.json のギャップ全域**に対して実行し、
   ギャップ内に「音の島」（オフマイクの相槌や、フルの文字起こしが落とした発話）が無いか照合。
   見つかったら該当区間だけを抜き出して再文字起こしし、words.json になくても保護区間に加える
3. 各保護区間は `[発話開始 − 0.3s, 発話終了(word) + 0.5s]` を最低ラインとする
4. drop_range が保護区間と 1ms でも重なる場合は、保護区間を削る方向ではなく **drop 側の境界を移動**
5. 確定後、各 drop_range 単体を切り出し `silencedetect` で「区間全体が無音、または除去対象の
   フィラー/言い直しのみ」であることを検証（声の島が残っていれば分割・短縮して再検証）
6. **レンダリング後**、保護フレーズに対応する箇所を出力 MP4 から全て切り出して聞き直し、
   語頭〜語尾が欠けていないことを最終確認する（onset_snap --check の 0 件確認とは別に必須）

## 固有名詞のホモフォン誤変換に注意

Whisper は同音異義語を人名・院名・役職名に誤変換しやすい（2026-07 とく歯科案件：
「医院」→「委員」「院長」→「委員長」「事業」→「授業」）。人名・医院名・役職名が出てくる
インタビューでは、確定前に (1) work_dir/出力先フォルダ名・ユーザー提供資料、(2) 動画フレーム内の
名札・ロゴ・スライド、(3) 公式サイトの Web 検索、の3経路で表記を裏取りする。裏取りできない
人名は焼き込まず候補を列挙してユーザーに確認する。

## テロップ設計ルール（smart-caption 鉄則に追加）

1. 各テロップの `start` = **テロップ先頭語の word 開始時刻**（発話開始と同時に表示の原則）
2. `end` = 最終語の word 終了 + 0.2s。**次テロップの start でクランプ**（重なり禁止）
3. `speaker` を必ず付ける（色分けの根拠）。質問=interviewer / 回答=respondent
4. 2行以内・1行 ≤ 16字目安。誤変換補正（イシュ→Issue 等）は文脈で
   - **総字数16字以内のカードは改行せず1行のまま**（2026-07 すすむ歯科でユーザー確定。
     「大したことは\nしてなくて」のような短文2行化はNG）。改行は総字数が1行上限を
     超えるカードだけ。焼き込み前に「\n を含み総字数 ≤16」のカードが0件であることを機械チェック
5. 「はい」「そうですね」など**テロップに載せない先行語がある場合、start はテロップ先頭語側**に置く
   （先行語の頭に置くと onset_snap の前方専用設計と整合しなくなる）

焼き込み前の機械チェック（全カードスキャン・全て0件を確認してから焼く）：

- **カード先頭が助詞・助動詞・活用の続きで始まっていないか**（に/を/が/は/で/と/という/た/ない 等。
  「はございますか」「という ことだったん」の単独カード化は前カード末尾に助詞を残す形で境界を引き直す）
- **隣接カードの末尾/先頭で文字が重複していないか**（2026-07 とく歯科実測：「〜状態に」|「にすれば〜」
  と「に」が両カードに二重出現。読むと「状態ににすれば」になる。突き合わせで機械的に検出できる）
- **単語・熟語・カタカナ語の分断が0件か**、各カード単独で意味が通るか
- Whisper の**聞き取り自体の誤り**（同案件：「もうどれを見れば」→「戻りを見たらいいか」と誤認識）は
  機械チェックでは拾えない。文脈上不自然な語（「戻り」等の唐突な名詞）は該当区間を聞き直して確認する

## 話者ラベル（speaker）の検証 — 挨拶の掛け合いは内容で判定できない（2026-07 追記）

Whisper は話者分離をしない。speaker は LLM が文脈で付けるが、**冒頭・末尾の挨拶の
掛け合い（「ありがとうございます／ました」「よろしくお願いします」の応酬）は両者が
同じ言葉を言うため、テキスト内容から話者を判定できない**。2026-07 とく歯科案件で、
末尾4枚（ありがとうございます→また今後とも→ありがとうございました→はいありがとうございました）
のうち3枚の speaker を取り違えて焼き込んだ実例あり。

対策（koetsu 確定前に必須）：

1. 同種の挨拶が2枚以上連続する区間（冒頭・末尾に多い）を「挨拶クラスタ」として全てリストアップ
2. カード間ギャップを手がかりにする：**直前カードと 0.5s 以上の無音を挟む挨拶は話者交代の
   可能性が高い**（今回の実例では 0.84s ギャップが交代点だった。地続きの発話はギャップほぼ 0s）。
   ただしヒューリスティックであり確定根拠にはしない
3. **確定根拠は音声そのもの**。該当区間を切り出して声質・音量差（オフマイク側は小さい）で
   判定し、LLM 側で確定できないカードは焼き込み前にユーザーへ「このカードはどちらの声か」を
   必ず確認する（取り違えて焼くと再レンダリング1回分の損失）
4. QC で挨拶クラスタ各カードのフレームを抽出し、色分けが音声と一致することを目視確認

## テロップ同期の要（今回の実測知見・変更禁止級）

- **Whisper の word 開始は「ポーズ明けの語」で 0.2〜0.7s 早く付く**（無音を語頭に含める癖）。
  word アンカーのままだと声より先にテロップが出る。→ `onset_snap.py` が前方スナップで補正（render_interview.py が自動実行）
- **遅れ方向のズレはほぼ出ない**ので、補正は「遅らせる方向のみ」
- 焼き込み表示はさらに **0.05s 先行**（`--lead`）。「表示が発話に遅れない」を構造的に保証
- 検証で出力を再文字起こしすると**ポーズ明けの語で偽の「遅れ」判定**が出る（再認識も同じ癖を持つため）。
  sync QC は `onset_snap.py --check`（エネルギー基準）を正とし、再認識ズレの個別値は鵜呑みにしない

## 顔出しNG（顔隠しオーバーレイ）案件の鉄則（2026-07 とく歯科で事故実測・必須）

顔隠しは「元動画に合成→顔隠し済み中間動画（例: `video_masked3.mp4`）を作る→以降のパイプラインは
中間動画を元動画として走らせる」構成にする（テロップが必ず顔画像の上のレイヤーになる）。このとき：

1. **render_interview.py の `--src` は必ず顔隠し済み中間動画を指す**こと。
   実事故：work_dir に正しい `video_masked3.mp4` があるのに `--src` に元動画を渡してレンダリングし、
   実写の顔が全編露出した MP4 を納品ファイル名で出力した。**work_dir に `video_masked*.mp4` が
   存在する案件では、レンダリング直前に `--src` のパスを声に出して確認**する
   - オーバーレイの配置は目分量で置かず**計測→計算→検証**で決める：
     元動画から冒頭・1/4・中間・3/4・終盤の5フレームを抽出し、対象者の髪の頭頂 y_top／
     アゴ先 y_chin／鼻筋の x（顔の中心線）を計測。x は中央値、y_top は最小値、y_chin は
     最大値を採用（＝動きの範囲全体を覆う箱）。頭部高さ h = y_chin − y_top
   - サイズ：高さ = **2.0×h**（アスペクト比維持。幅が 2.2×h を超える画像なら幅 = 2.2×h 基準に切替）。
     水平：画像中心 x = 鼻筋の x（画面中心・体の中心ではなく**顔の中心線**）。
     垂直：画像の下端 = y_chin + 0.25×h（アゴと首元まで覆う。上端が頭頂より上に出るのが正しい）。
     画像高が画面高の **45% を超えたら 45% にクランプ**し下端合わせ優先。位置は全編固定（追従なし）
   - 合成は**元動画に対して最初に**行い、crf 18／音声コピーで顔隠し済み中間動画を作る。
     以降のカット・整音・テロップは中間動画を元動画として通常パイプラインで実行
     （＝顔画像が必ずテロップの下のレイヤーになる）
   - 露出が1件でも出たら「中心はそのまま、サイズ10%ずつ拡大」で再合成・再検証。
     バランス基準：イラストの顔が実写の顔と同じ位置・幅は肩幅を超えない・
     下端がテロップ表示領域（画面下部）にかからない
2. **QC はスポットフレーム数枚では不十分**。出力 MP4 から 2秒間隔で全編フレームを抽出し
   コンタクトシート1枚に並べて目視する（85〜90枚が1枚の画像で確認できる）。
   スポット3〜4枚のQCはこの事故を通過させた実績がある（=信用しない）
3. お辞儀・立ち座り等の大きい動きの区間は追加で 0.25〜0.5秒間隔で確認
4. 事故ファイルを発見したら削除せずユーザーに確認。リネームで残す場合は
   `_NG顔露出注意` 等、開けば分かる名前にして誤共有を防ぐ

## レンダリング方式（環境制約）

- この環境の ffmpeg には **subtitles / ass / drawtext フィルタが無い** → ASS 焼き込み不可
- **やってはいけない**: `-loop 1 -i png` ×N の overlay 直列（49枚で10分超・タイムアウト）
- **正解**: 全テロップを ffconcat 1トラック（フル画面PNG + duration 指定・ミリ秒整数で累積誤差ゼロ）
  にして overlay 1段。49枚・165s 素材で約1分
- 音声は loudnorm 2パス（測定値埋め込み）で -14 LUFS / TP -1.5。カット境界は 12ms フェードでポップ除去

## QC（納品前必須）

1. `onset_snap.py --check --koetsu koetsu_out.json --media <出力mp4>` → 追加補正 0 件を確認
2. ラウドネス実測: `-af loudnorm=print_format=json` で I=-14±0.5 / TP ≤ -1.3
3. テロップ表示開始直後（start+0.05）のフレームを2〜3枚抽出して目視（色・位置・被り）
4. 尺 = keep_segments 合計と一致
5. 「保護フレーズ検証」でリストアップした箇所を出力 MP4 から全て切り出して再生し、語頭〜語尾の欠けが無いことを確認
6. 冒頭・末尾の挨拶クラスタ各カードのフレームを抽出し、色分け（speaker）が音声と一致することを確認
   （話者取り違えは挨拶の掛け合いで起きやすい。「話者ラベルの検証」参照）
7. 途中で `end_time` を詰めた（末尾の発話をカットした）場合は、出力末尾 0.5s の RMS 包絡で
   声が無音まで自然減衰して終わることを確認（「カット設計ルール」6 参照）
8. 顔出しNG案件は全編コンタクトシートで顔露出 0 件を確認（「顔出しNG案件の鉄則」参照）

## プレミア用テロップなし納品も同時に出す（標準運用・2026-07 ユーザー要望）

焼き込み版の納品時、**同じ work_dir のデータからプレミア編集用セットも毎回一緒に出す**
（ユーザーは後からプレミアで手直しする運用。別依頼を待たない）。
出力先は `work_<stem>/テロップなし納品/`。スクリプトは notelop-deliver スキルの `scripts/`。

1. cutplan.json → keep_segments.json に変換（drop_ranges の補集合 + end_time）：

   ```python
   keep, cursor = [], 0.0
   for s, e in drops: keep.append([cursor, s]); cursor = e
   keep.append([cursor, end_time])
   ```

2. `cut_notelop.py --src <元動画> --keep keep_segments.json --out テロップなし納品/<stem>_テロップなし.mp4 --workdir <work>`
3. `map_koetsu.py --koetsu koetsu.json --keep keep_segments.json --out koetsu_final_notelop.json`（src時刻→カット後時刻）
4. koetsu.json の speaker から speakers.json（`["I","A",...]`）を作り
   `split_srt_by_speaker.py` で `<stem>_インタビュアー.srt` / `<stem>_回答者.srt`、
   export-deliver の `to_srt.py` で一体版 `<stem>_テロップ編集用.srt`
5. `export_premiere_timeline.py --src <元動画> --keep keep_segments.json --out-edl <stem>_カット編集点.edl --out-xml <stem>_カット編集点.xml --fps 30`
   （元素材参照＋編集点入りシーケンス。プレミアでカット位置を手直しできる）
   - **元動画に回転メタデータ（rotation≠0）が付いている場合はスクリプトがエラーで止まる**
     （Premiere は XML 経由だと回転を無視して上下逆になる・2026-07 すすむ歯科で実測）。
     正立化した `<stem>_編集用素材.mp4` をテロップなし納品/ 内に作り、それを --src に渡す
     （手順は notelop-deliver スキル 3b 参照）
6. `テロップなし納品/_workdata/<stem>/` に words.json / keep_segments.json / koetsu_final.json / speakers.json をコピー

QC: MP4尺=カット合計、EDLイベント数=keep区間数、XMLがwell-formed、フレーム1枚で焼き込み無しを目視。
詳細な手順・プレミア側の運用説明は notelop-deliver スキル参照。

## 納品後の修正リビジョン（2026-07 とく歯科 徳田院長_研修後 rev2 で確立）

納品済み動画に「ここをカットして／このテロップ直して」の修正依頼が来たときの手順。
**ゼロから作り直さない**。work_dir の words.json / cutplan.json / koetsu.json を流用し、
入力2ファイルを直して render_interview.py を再実行するだけでよい（スクリプトが
master.wav / telop_png / filter_* / koetsu_out.json を毎回作り直すため、中間ファイルの
手動更新は不要）。

1. **work_dir を探す**: 出力先ディレクトリ直下の `work_<stem>/`。spec.json の `work_dir` が正
2. **編集前バックアップ**: `cutplan.json` / `koetsu.json` を `*.bak_before_revN` でコピー
3. **ユーザーの時刻指定は完成動画（カット後）のタイムライン**（例:「3:38」「4:22」）。
   cutplan の drop_ranges で **source 時刻へ逆写像**してから words.json / koetsu.json を照合する：

   ```python
   def final_to_source(t_final, drops):  # drops はソート済み [[s,e],...]
       cum, prev_end = 0.0, 0.0
       for s, e in drops:
           kept = s - prev_end
           if cum + kept >= t_final:
               return prev_end + (t_final - cum)
           cum, prev_end = cum + kept, e
       return prev_end + (t_final - cum)
   ```

   実測（rev2）: 完成動画 3:38(218s) → source 228.5s。カット済み分だけ後ろへズレるので、
   完成タイムラインの時刻のまま words.json を検索すると**別の発話にヒットする**。必ず逆写像してから探す
4. **言い直しカットの追加**: words.json の word 時刻で境界を確認し（言い直し前テイクの
   先頭語 start 〜 本テイクの先頭語 start）、新しい drop を追加。**既存の drop と重なる／
   包含される場合は1つに統合**する（例: 新規 [227.8, 234.26] が既存 [227.8,228.16] と
   [232.69,234.06] を包含 → 3つを1つに置換。重複 drop はマッパーの除去量を狂わせる）
5. **カットで丸ごと消えるテロップは koetsu.json から項目ごと削除**。残すと
   render_interview.py が `caption too short after mapping` で止まる（安全弁として機能する
   ので、消し忘れは実行時に必ず検出される）
6. **テロップ文言だけの修正**（誤字・誤変換）は koetsu.json の `text` を直すだけ。
   カット・音声には触れない
7. 同じ引数で render_interview.py を再実行。出力名は `<stem>_fulltelop_revN.mp4`。
   **旧版は上書きせず残す**。`--styles` 指定を忘れない（styles.json に案件固有の色が
   入っていることが多い。忘れると既定の #FF3399 で焼かれて再レンダリング1回分の損失）。
   SRT は work_dir に出るので、納品ディレクトリへ revN 名でコピーする
8. **リビジョン専用QC**（通常QCに加えて）:
   - 尺の差分 = 追加カットの合計秒数と一致することを確認（rev2 実測: 574.40→569.67s、
     差分 4.73s = 削除区間 6.46s − 統合で消えた既存 drop 1.73s）
   - 修正した各箇所の表示中フレームを出力 MP4 から抽出して目視
     （カット跡の自然さ・修正文言が焼き込みに反映されているか）
